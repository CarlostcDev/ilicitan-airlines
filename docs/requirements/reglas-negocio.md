# Reglas de negocio

Las reglas de negocio definen las condiciones y restricciones que deberán cumplirse durante el funcionamiento de Ilicitan Airlines, independientemente de la interfaz utilizada.

| ID        | Regla                                                                                                                                                                                                         |
| --------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **RN-01** | Cada dirección de correo electrónico podrá estar asociada a una única cuenta de usuario.                                                                                                                      |
| **RN-02** | Una cuenta creada mediante correo electrónico y contraseña, Google o Apple no podrá utilizar posteriormente el mismo correo electrónico para crear una segunda cuenta mediante otro método de registro.       |
| **RN-03** | Un usuario podrá realizar múltiples reservas, siempre que cada una cumpla las condiciones establecidas por el sistema.                                                                                        |
| **RN-04** | No se podrá realizar una reserva para un vuelo cuya fecha de salida ya haya pasado.                                                                                                                           |
| **RN-05** | Un usuario únicamente podrá consultar y gestionar las reservas asociadas a su propia cuenta.                                                                                                                  |
| **RN-06** | Una reserva podrá incluir como máximo 8 pasajeros.                                                                                                                                                            |
| **RN-07** | La clase de viaje seleccionada para una reserva se aplicará a todos los pasajeros incluidos en dicha reserva.                                                                                                 |
| **RN-08** | Los usuarios registrados mediante correo electrónico y contraseña recibirán una fotografía de perfil predeterminada cuando no dispongan de una fotografía propia.                                             |
| **RN-09** | Los usuarios registrados mediante Google utilizarán como fotografía de perfil la proporcionada por su cuenta de Google cuando esté disponible; en caso contrario, se utilizará una fotografía predeterminada. |
| **RN-10** | Los usuarios registrados mediante Apple utilizarán como fotografía de perfil la proporcionada por su cuenta de Apple cuando esté disponible; en caso contrario, se utilizará una fotografía predeterminada.   |
| **RN-11** | Un vuelo deberá tener un aeropuerto de origen y un aeropuerto de destino diferentes.                                                                                                                          |
| **RN-12** | Los administradores no accederán a las funciones destinadas a los usuarios normales, sino únicamente a las funciones administrativas correspondientes a su rol.                                               |
| **RN-13** | Los administradores podrán importar y exportar información del sistema mediante archivos en formato CSV.                                                                                                      |
| **RN-14** | Un asiento no podrá estar asignado simultáneamente a más de un pasajero en un mismo vuelo.                                                                                                                    |
| **RN-15** | Un vuelo no podrá tener más pasajeros que la capacidad máxima de la aeronave asignada.                                                                                                                        |
| **RN-16** | La aeronave asignada a un vuelo deberá ser compatible con las características y condiciones establecidas para dicho vuelo.                                                                                    |
| **RN-17** | Los datos de una reserva confirmada deberán conservarse independientemente de que el usuario cierre sesión o deje de utilizar temporalmente la aplicación.                                                    |
| **RN-18** | Las operaciones administrativas estarán limitadas a las funciones autorizadas para el rol correspondiente.                                                                                                    |
| **RN-19** | La disponibilidad de un asiento deberá actualizarse cuando sea asignado a un pasajero, evitando que pueda ser asignado posteriormente a otro pasajero del mismo vuelo.                                        |
| **RN-20** | Una reserva de ida y vuelta deberá estar formada por un vuelo de ida y un vuelo de regreso compatibles con las fechas seleccionadas.                                                                          |
| **RN-21** | Las condiciones de modificación y cancelación de una reserva deberán respetar las condiciones establecidas para el billete adquirido.                                                                         |
| **RN-22** | La disponibilidad del check-in estará determinada por el tipo de vuelo y el periodo establecido para realizarlo.                                                                                              |
| **RN-23** | El check-in de un vuelo internacional podrá realizarse desde 48 horas antes de su salida y hasta 2 horas antes de la misma.                                                                                   |
| **RN-24** | El check-in de un vuelo nacional podrá realizarse desde 24 horas antes de su salida y hasta 2 horas antes de la misma.                                                                                        |
| **RN-25** | El check-in se realizará de forma independiente para cada vuelo incluido en una reserva.                                                                                                                      |
| **RN-26** | En una reserva de ida y vuelta, el check-in del vuelo de ida no implicará el check-in del vuelo de regreso.                                                                                                   |
| **RN-27** | El check-in de una reserva se realizará para todos los pasajeros asociados al vuelo seleccionado.                                                                                                             |
| **RN-28** | Cuando un pasajero no disponga de un asiento asignado al realizar el check-in, deberá recibir uno de los asientos disponibles del vuelo.                                                                      |
| **RN-29** | Una vez realizado el check-in de un vuelo, no podrá volver a realizarse el proceso de check-in sobre ese mismo vuelo.                                                                                         |
| **RN-30** | Las tarjetas de embarque generadas corresponderán únicamente a los pasajeros y vuelos que hayan completado el proceso de check-in.                                                                            |
| **RN-31** | Los datos API/APIS de los pasajeros podrán ser modificados durante el proceso de check-in antes de su confirmación.                                                                                           |
| **RN-32** | Los datos de un usuario no podrán ser modificados ni eliminados por otro usuario que no disponga de los permisos administrativos correspondientes.                                                            |
